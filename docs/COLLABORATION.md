# Как Диане и Рите работать вдвоём

Вычисленные split manifests и `data/derived/` не коммитятся. Feature/landmarker
команды запускайте одним процессом записи на checkout; разные ветки и checkout
могут считать независимо. Конфигурации исследования (`config/research.yaml`,
`config/candidates.yaml`) общие: изменения протокола/метрик согласуйте до объединения
результатов. Credentials и checkpoint paths локальны; храните локальный YAML вне Git
и передавайте его через `--config`. Результаты разных config_id не смешиваются.

## Один датасет — одна папка и отдельная ветка

Например, Диана добавляет `adult`, а Рита — `heart_disease`:

```text
data/raw/adult/metadata.yaml
data/raw/heart_disease/metadata.yaml
```

Эти файлы можно менять независимо. Названия папок стабильны и совпадают с
`dataset_id`. Используем snake_case: `credit_default`, а не `Credit Default`.
Не меняйте ID после добавления без совместного решения — это идентификатор набора,
а не просто красивое название.

Пример работы Дианы:

```bash
git switch main
git pull
git switch -c datasets/adult
# вручную положить данные и создать metadata.yaml
python scripts/validate_dataset.py adult
python scripts/register_dataset.py adult
git add data/raw/adult/metadata.yaml
git add data/registry/datasets.csv
git diff --cached
git commit -m "Add Adult dataset metadata"
```

Если основная ветка у вас называется `master`, замените `main` на `master`.
Рита аналогично использует ветку `datasets/heart_disease`. Не создавайте обе ветки
для одного датасета без договорённости. Перед добавлением сравните источник,
external_id и notes: другой файл может оказаться версией уже добавленного набора.

## Какие файлы общие

| Файлы | Как работать |
|---|---|
| `data/raw/<ваш_id>/metadata.yaml` | Независимо в своей папке |
| Реальный CSV/XLSX/Parquet | Локально; Git их игнорирует |
| `data/registry/datasets.csv` | Общий производный файл; не редактируем вручную |
| `config/project.yaml`, `config/datasets.yaml` | Менять по договорённости, они влияют на весь проект |
| Код и документация | Отдельные ветки под конкретное изменение |

Не запускайте две команды регистрации одновременно в одном checkout. Каждая
запись атомарна, но механизм не предназначен для конкурентного редактирования
реестра несколькими процессами на общей папке.

## Как избежать конфликтов в реестре

Метаданные — источник истины. CSV — только восстанавливаемый индекс. Не выбирайте
вручную строки из двух конфликтующих CSV, если проще выполнить пересборку.

После объединения веток:

1. Убедитесь, что обе папки с `metadata.yaml` присутствуют.
2. При конфликте CSV сначала возьмите любую целую версию **только этого файла**:

   ```bash
   git checkout --ours -- data/registry/datasets.csv
   ```

3. Пересоберите индекс:

   ```bash
   python scripts/register_dataset.py --rebuild
   python scripts/list_datasets.py
   ```

4. Проверьте статусы. Добавьте заново полученный CSV в разрешение конфликта:

   ```bash
   git add data/registry/datasets.csv
   ```

5. Завершите merge обычным способом.

Пересборка детерминирована при одинаковых входных файлах и окружении: строки
отсортированы по ID, timestamps отсутствуют. Не применяйте команды разрешения
конфликта ко всему проекту — они приведены только для производного CSV.

## Если у второго человека нет самого датасета

После `git clone` будут код, `metadata.yaml`, индекс и `_toy_binary`. Больших
исходных файлов не будет. Их нужно скачать вручную по `source.url` и поместить
в папку под именем `file.name`.

До скачивания локальная пересборка показывает `missing_file`. Это нормальное
состояние, а не повод удалять метаданные коллеги. Старый сохранённый CSV может
показывать `valid` от другого участника: локальную доступность проверяет validate.

Если оба участника хотят одинаковые статусы реестра, у них должны быть одинаковые
исходные файлы. Передавать их можно согласованным способом вне Git, соблюдая
условия источника. Не добавляйте файл принудительно через `git add -f`.

В notes полезно писать номер версии, дату выгрузки источника или ссылку на описание,
но не секреты и токены. Если файл обновился, сообщите об этом друг другу,
обновите метаданные при необходимости и повторно зарегистрируйте набор.

## Проверка перед объединением

```bash
python scripts/validate_dataset.py ваш_dataset_id
python scripts/register_dataset.py --rebuild
python scripts/list_datasets.py
pytest
git diff --cached
```

При отсутствии чужих исходных файлов `--rebuild` может вернуть код `1` и записать
`missing_file`; внимательно прочитайте причины. Не объявляйте такие наборы
проверенными локально. Проверка кода на маленьких тестовых файлах не требует
скачивания реальных датасетов.
